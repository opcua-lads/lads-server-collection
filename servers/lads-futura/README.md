# LADS Futura Connect Xtra (Aber Instruments)

Example server for the LADS OPC UA model of the Aber Instruments Futura Connect Xtra (FUTURA capacitance probe with optional SPECTRA cell density sensor).

- NodeSet: `nodesets/FuturaConnect.xml` (namespace `http://aberinstruments.com/FuturaConnect/`), generated by `nodesets/generators/gen_futura.py`
- Types: `FuturaConnectDeviceType`, `FuturaUnitType`, `SpectraUnitType` (static model, ParameterSets and ProgramTemplates are part of the types)
- The server creates exactly one device instance.

## Run

```
npm run lads-futura                      # port 4848
npm run lads-futura -- -p 4855           # other port
npm run lads-futura -- --autostart       # start the simulation immediately
npm run lads-futura -- --data file.csv   # replay recorded data (time_h, capacitance, conductivity, temperature)
```

## Simulator

A `Simulator` object below the device replays a fermentation in time lapse (built-in 250 h batch or CSV file).
Nodes: `Start()`, `Stop()`, `Reset()`, `Status`, `TimeLapse` (process seconds per real second), `ProcessTime`, `Duration`, `Loop`, `SpectraInstalled`, `DataSource`.
The SPECTRA values follow the model of the FUTURA SPECTRA User Manual (2819-09-00, sections 13/14): Cole-Cole function (Eq. 7), `DeltaCapacitance = 9 P r Cm / 4` (Eq. 8) and `CriticalFrequency = 1 / (2 pi r Cm (1/sigma_i + 1/(2 sigma_e)))` (Eq. 9). The probe capacitance is the Cole-Cole value at 580 kHz; the model is inverted to volume fraction, cell diameter, cell number and medium conductivity. Cole-Cole alpha has no closed formula in the manual and follows a typical time course.
`BioMassMeasurement` = (`Capacitance` - ZeroValue) x BioMassMultiplier with the `CalibrationValues` of the function (start values 4 pF/cm and 1.0; both writable). With 1.0 the reading is the viable cell density in 10^6 cells/ml (rule of thumb of the manual: 1 pF/cm = 10^6 cells/ml, Cell Culture mode).
With `SpectraInstalled = false` the SPECTRA functions are disabled and its unit stays stopped.

## Commands

ZeroNow, ClearZero, CleanPulseNow and IncrementAutoclaveCount are TwoStateDiscreteControlFunctions for clients that cannot call methods; the same commands are the ProgramTemplates Zero, ClearZero, CleanPulse and IncrementAutoclaveCount (`StartProgram` of the Futura unit). Both routes behave the same (`src/commands.ts`):
- `ControlFunctionState` is always Running
- writing `TargetValue = true` (or `StartProgram`) while `CurrentValue` is true returns `BadInvalidState`
- otherwise an Info event "<Function> initiated" is raised, `CurrentValue` becomes true (executing), `TargetValue` returns to false after about 100 ms and `CurrentValue` after about 1000 ms
- `SlopeCalibration` is not simulated (`BadNotSupported`)

Effects on the simulated device:
- **Zero**: `BioMassMeasurement.CalibrationValues[0]` = current Capacitance; `ScanCapacitance.CalibrationValues` = current `ScanCapacitance.SensorValue` (the scan is then reported relative to this zero)
- **ClearZero**: both zeros are reset to 0 (the BioMassMultiplier is kept)
- **IncrementAutoclaveCount**: `AutoclaveCycles` of the probe is increased by 1

`MeasurementMode` (MultiStateDiscreteControlFunction): `ControlFunctionState` is always Running, `TargetValue` and `CurrentValue` start as CellCulture. Writing a different mode raises an Info event "Measurement mode changed to <mode>" and sets `CurrentValue = TargetValue`; writing the current mode does nothing. The mode does not influence the simulated values.

## Device health and alarms

The `StatusFlags` register (UInt16) sits on the device next to `DeviceHealth`; the alarms of `DeviceHealthAlarms` are derived from its bits (`src/health.ts`), their source is the affected component (Probe, Futura or Spectra), and `DeviceHealth` is the worst active alarm (NAMUR NE 107). The Simulator object has a writable `StatusFlags` to trigger them: bits 0 capacitance, 1 conductivity, 2 temperature out of range, 3 probe leakage, 4 clean leakage, 6 FUTURA memory, 7 probe memory, 9 no probe, 10 signal simulator connected (sets `SignalSimulatorConnected`), 12 curve fit error. Events are raised when an alarm becomes active or inactive and whenever `DeviceHealth` changes. Note: `DeviceHealth = FAILURE` aborts running functional units (behaviour of `LADSDeviceHelper`).
